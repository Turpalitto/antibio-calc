## 3. Policy (Task 3)
`DOSE_NORMALIZATION_POLICY.md`: never generate a dose; a route is recovered only when EXACTLY ONE
route family matches literal source text (ambiguous "или" branches always left unset); every
recovered field carries `FieldProvenance` tagged `source_store="normalized_regimens+text_normalization"`
so it is permanently distinguishable from the original LLM extraction; ambiguity always routes to
REVIEW/stays REJECT, never defaults to PASS.

## 4. Honest self-correction (recorded, not hidden)
The initial exploratory audit regex for "route present in text" used an overly permissive pattern
(matching bare single-character prepositions like `в`/`м`, which appear in nearly every Russian
sentence) and reported 296 "safely fixable" cases. Once the ACTUAL safety-reviewed matcher was
implemented (specific word-stem patterns only: `внутривенн\w*`, `в/в\b`, etc., with a hard ambiguity
check requiring exactly one route family match), the real, correct count is **13**. This correction
is recorded in `RC024_DOSE_AUDIT_REPORT.md` directly rather than left as a discrepancy between the
audit and the implementation — the smaller, correct number is reported, not the larger, wrong one.

## 7. Can we proceed to P6?
**Same conclusion as P5.3, now with corrected numbers:** the engineering layer is sound (23/23 tests
pass, 100% explainability, honest metrics), but **the real blocker to P6 is not engineering — it is
that 675 regimens (59.6% of all REJECTs) are guidelines describing drug classes/alternatives rather
than single dosed regimens.** This is not a bug to fix; it is a **regimen-modeling scope decision**:
should ANTIBIO's `ClinicalRegimen` model support a "class-level recommendation" (no single dose,
lists eligible drugs) as a distinct, valid object type, or should these 675 be excluded from the
regimen corpus entirely? That decision determines whether 59.6% of the guideline corpus is usable at
all, and must be made by clinical governance (Sign-off Authority / Medical QA Lead per
`CLINICAL_VALIDATION_FRAMEWORK.md`), not inferred here.

**Recommendation, unchanged from P5.3:** P6 (engine consuming assembled regimens) still requires
a populated approval pipeline (physician review capacity) and now ALSO requires the class-level-
regimen modeling decision above before the corpus's true usable size is known. Until then, only
569 PASS + 987 REVIEW (eligible for the review queue) = 1,556 of 2,675 regimens (58.2%) are on a
path toward `PHYSICIAN_APPROVED`; the remaining 41.8% await a modeling decision, not more
engineering effort.
