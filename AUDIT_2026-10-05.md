## 1. Вердикт

**Ядро продукта прочное, но два «ворота» в HEAD красные, и клавиша безопасности переведена в положение OFF.**

- Инженерная дисциплина выше среднего: fail-safe дизайн API (никогда молча не рекомендовать), traceability-модель внутри движка, статический сервер с хорошей санитацией путей, owner-token через `compare_digest`, чистая история от секретов.

## 2. Критические находки (CRITICAL)

### D2 — Fail-closed гейт выключен по умолчанию; 4 записи разблокированы силой
- `db/build_db.py:53` — `unblock_all: bool = True`; `--fail-closed` только опцией CLI (`:137,148`); гейт вызывается с `unblock_all=not args.fail_closed` (`:148`).
- В собранной `db/antibio_db.json` и в поставляемом `antibiotic_calc.html`: **0** записей с `calculation_blocked=true` (раньше — 119, см. `7a2b2cf` от 2026-09-10).
- В источнике `db/diseases/respiratory.json` **4 записи явно помечены blocked** (`sinusitis_adult`, `sinusitis_child`, `pharyngitis_adult`, `pharyngitis_child` — причины «PDF pending» / «pending owner review») — и они проходят в релиз принудительно.
- Юнит-тест не страхует: `src/tests/test_build_db.py:128` передаёт фейковый гейт с 3-арг. сигнатурой → молча уходит в `except TypeError` fallback (`build_db.py:86-87`), реальный дефолт не проверяется.
- **Следствие:** дозы считаются для нозологий, чей источник не верифицирован — прямое нарушение собственного закона fail-closed проекта.
- **Фикс:** дефолт `--fail-closed` (или честный отказ от гейта + удаление 4 blocked-записей из источника), тест на реальную сигнатуру гейта.

## 3. Высокие находки (HIGH)

### D4 — Traceability law не доказуем через v1-транспорт
- Внутри движка цепочка есть (`StageTrace`, `stages/trace.py`, excluded-with-reason), v2/personal её отдаёт (`personal/recommender.py:142-230`).
- v1 выдаёт `_minimal_recommendations` (`api/service.py:154-184`): только rank/regimen_id/guideline_id/therapy_line + safety-флаги; контракт (`contract.py:179-187`) ключа trace не содержит. На 7 вопросов Clinical Traceability Rule ответить из ответа v1 нельзя.

### S-2 — Loopback-гейт движка обходится через прокси server.js
- `_loopback` (`api/app.py:83-92`) проверяет peer+hostname+Origin; но прокси `server.js:232-246` заменяет Host (HOP_BY_HOP, `:220-231`) → движок всегда видит 127.0.0.1.
- `HOST` по умолчанию `127.0.0.1` (`server.js:75`), но при `HOST=0.0.0.0` LAN-клиент без токена получает `/v2/recommend` и personal-reads. Мутации защищены owner-token, чтения — нет.

### S-3 — Живой CDN в CSP при PHI в sessionStorage
- `antibiotic_calc.html.template:9` грузит `cdn.tailwindcss.com`, CSP его разрешает (`server.js:88`); история пациента (Ф.И.О., диагноз, препараты) пишется в `sessionStorage` (`:3141,:3153`), opt-in, без TTL.
- Компрометация CDN/шрифтов (также `cdnjs`, `fonts.googleapis`) исполняется в origin с `unsafe-inline` и видит PHI. **Фикс:** self-host Tailwind/fonts (сборка уже single-file).
