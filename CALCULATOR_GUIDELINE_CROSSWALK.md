# Связь «клинические рекомендации ⇄ калькулятор» — модель, аудит, контракт

> Артефакт создан 2026-09-10. Статус: **реализовано, проверено тестами**.
> Уровень: **навигационный** (`NAVIGATION_ONLY`). Не является одобрением схем,
> не снимает блокировку расчёта, не входит в рекомендательный контур.

---

## 1. Проблема, которую закрыла эта работа

В репозитории жили две независимые половины:

| Половина | Где лежит | Ключ записи |
|---|---|---|
| **Калькулятор** | `db/antibio_db.json` → `antibiotic_calc.html` | `cr_id` = рубрикатор МЗ (`858_1`) |
| **Корпус КР** | `clinical_engine/resources/diagnosis_index.json` (895 записей, 294 КР) | `guideline_id` = внутренний id `metadata.sqlite` (`1269`) |

**Проверено 2026-09-10:** из 82 уникальных номеров рубрикатора, используемых
калькулятором, в корпусе встречается ровно **один** — `912`. И это ложное
срабатывание: `КР912_1` «Неонатальный сепсис» против корпусного 912 «Системный
склероз». То есть **соединять две стороны по идентификатору нельзя в принципе** —
пространства имён не пересекаются, а совпадение номера даёт клинически неверную
связку.

Отсюда — «калькулятор ничего не знает про корпус КР», и наоборот.

### Попутно найденный дефект данных (исправлен)

`normalize_mkb()` был скопирован **в трёх модулях**
(`dosa_to_db_mapper.py`, `dosa_source_contract.py`, `extension_sources.py`) и ни
один не разбивал склеенные строки кодов. Результат в
`db/diseases/extended_dosa.json`:

```json
"mkb10": ["C83.5, C91.0, C95.0"]   // 16 нозологий
"mkb10": ["B20-24"]                // 1 нозология, диапазон блока
```

Такой код невидим для **любого** соединения по МКБ-10. Исправлено:
единый модуль `src/pipeline/extraction/icd10.py` + регенерация данных.

## 2. Модель связи

Единственные корректные ключи соединения — **МКБ-10** и, как резерв,
**точное нормализованное название**.

| Метод | Правило | Уверенность |
|---|---|---|
| `ICD10_EXACT` | Полное совпадение кода (`O91.0` ↔ `O91.0`) | `HIGH` |
| `ICD10_BLOCK` | Совпадение 3-символьного блока (`G00.1` ↔ `G00.9` → `G00`) | `MEDIUM` |
| `TITLE_EXACT` | Точное совпадение нормализованного названия КР/синонима | `LOW` |

Приоритет: `ICD10_EXACT` > `ICD10_BLOCK` > `TITLE_EXACT`. Если для одной КР
сработали несколько методов — сохраняется сильнейший.

**Явно НЕ используется:** совпадение `cr_id` ↔ `guideline_id` (см. §1).

Нормализация МКБ-10 (обе стороны):
- разбиение склеек по `,` и `;`;
- раскрытие диапазонов блоков (`B20-24` → `B20…B24`); диапазоны через букву
  (`A99-B01`) и обратные (`B24-20`) **не раскрываются** — коды не выдумываются;
- регистронезависимость, дедупликация с сохранением порядка;
- в кроссволке некорректные токены отбрасываются (строгая валидация), в
  `icd10.normalize_mkb` — сохраняются (первоисточник не теряется, INV-09).

| `db/source_gate_report.py` | Почему расчёт закрыт и что делать дальше |

### Форма записи связи

```json
{
  "disease_id": "mastitis_puerperal",
  "disease_name": "Послеродовой мастит",
  "cr_id": "858_1",
  "guideline_id": "1759",
  "guideline_title": "Воспалительные заболевания молочных желез",
  "guideline_years": [2024],
  "method": "ICD10_EXACT",
  "confidence": "HIGH",
  "matched_icd10": ["N61", "O91", "O91.0", "O91.1", "O91.2"],
  "diagnosis_names": ["Лактационный мастит", "Мастит (эмпирическая АБТ)", "..."]
}
```

В сборку калькулятора уходит компактная проекция (без `diagnosis_names`):
`{guideline_id, title, years, method, codes}` → `recommendations[].guideline_links`,
плюс сводка `meta.guideline_crosswalk`.

## 4. Результат на текущих данных

```
Нозологий в калькуляторе:      120
Со связью к корпусу КР:         98  (81.7%)
Без связи:                      22
КР корпуса всего:              294 guideline_id  (193 уникальных названия,
                                                 81 название делят несколько КР)
Затронуто связью:              199 guideline_id  (67.7% корпуса)
Не затронуто (зеркало):         95 guideline_id
Всего связей:                  263
  ICD10_EXACT                  181
  ICD10_BLOCK                   82
  TITLE_EXACT                    0
```

Перепись корпуса ведётся по `guideline_id`, а не по названию: 81 название
делят 182 разных `guideline_id` — это разные ревизии и годы одного документа
(«Язвенный колит» — 4 id: 1296/1466/1835/1836, годы 2021/2024/2025). Счёт по
названиям давал 193 и делал покрытие арифметически невозможным — «199 из 193».

22 нозологии без связи перечислены в `unmatched_diseases` с причиной
`NO_CORPUS_ENTRY_FOR_ICD10_OR_TITLE` — это честный ответ «в извлечённом корпусе
нет КР с этим МКБ-10», а не провал связки. Примеры: `prostatitis` (N41),
`scarlet_fever` (A38), `nec` (P77), `impetigo` (L01), `sepsis_adult` (A40/A41).

Зеркальная сторона — 95 КР корпуса, до которых не дотягивается ни одна нозология
калькулятора, — перечислена в `unlinked_guidelines` с причиной
`NO_CALCULATOR_DISEASE_MATCHES_ICD10_OR_TITLE`. Это вход для планирования
новых нозологий, а не дефект связки: большинство таких КР вообще не про
антибиотики («Опухоли головного и спинного мозга у детей», «Экзема»).
Покрытие замыкается точно: `linked 199 + unlinked 95 = 294`, пересечение пусто
(фиксируется тестом на отгруженном артефакте).

Актуальные цифры всегда печатает:
```bash
python -m clinical_engine.crosswalk          # проверить синхронность
python -m clinical_engine.crosswalk --write  # пересобрать
```

## 5. Контракт безопасности (неизменяемый)

1. **Навигация, не решение.** Панель и эндпоинт не возвращают доз, не ранжируют
   препараты и не участвуют в `Engine.recommend()`.
2. **Блокировка расчёта не трогается.** `attach_guideline_links` пишет только
   `guideline_links` и `meta.guideline_crosswalk`. Поля
   `calculation_blocked` / `source_verification_status` /
   `calculation_block_reason` принадлежат исключительно `calculator_source_gate.py`.
   Тест `test_crosswalk_never_marks_anything_as_approved_or_unblocks` это фиксирует.
3. **Fail-closed на рассинхрон.** Если `calculator_crosswalk.json` не соответствует
   своим входам, `db/build_db.py` **падает**, а не встраивает устаревшую
   провенанс-информацию. `CalculatorCrosswalk.load()` бросает исключение вместо
   ответа «связей нет».
4. **Детерминизм.** Один и тот же вход → байт-в-байт тот же артефакт. Хеш входа
   считается только по полям, которые связка реально читает
   (`id, name, synonyms, cr_id, mkb10`), поэтому запись `guideline_links` обратно
   в БД не выглядит как дрейф. Проверено: SHA-256 `db/antibio_db.json` идентичен
   после `--attach-only` и после полной пересборки.
5. **URL не выдумываются.** У всех 895 записей корпуса `source_url` пуст —
   связка его не синтезирует. Ссылка на рубрикатор берётся только из собственного
   `source_url` нозологии калькулятора.
6. **Соответствие `AGENTS.md`.** «Never connect Clinical Engine» относится к
   подключению движка к выдаче рекомендаций. Этот слой рекомендаций не выдаёт.

## 7. Очередь врачебной проверки блочных связей

Связь `ICD10_BLOCK` правдоподобна, но не доказана: «Воспалительные поражения
позвоночника» дотягивается до `pid` через блок `A18`, потому что у нозологии есть
`A18.2`. Верно это или нет — **решает только врач**.

`clinical_engine/crosswalk/review_queue.py` ранжирует все 82 такие связи.
Инструмент вычисляет исключительно **структурные** признаки и не выносит
клинических вердиктов; артефакт помечен `purpose: PHYSICIAN_REVIEW_ONLY`.

| Категория | Признак | Важность | Кол-во |
|---|---|---|---|
| `EXTERNAL_CAUSE_ONLY` | единственное совпадение — код внешних причин МКБ-10 (глава XX), а не болезни | HIGH | 1 |
| `AGE_DIRECTION_CONFLICT` | заголовок КР называет популяцию, которую `age_groups` нозологии исключает | HIGH | 4 |
| `BLOCK_ONLY_DISEASE` | у нозологии нет ни одной связи по точному коду | MEDIUM | 19 |
| `COARSE_SHARED_BLOCK` | одна КР блочно связана с несколькими нозологиями — блок их не различает | MEDIUM | 15 |
| `ROUTINE` | структурных подозрений нет, но проверка всё равно нужна | LOW | 43 |

Побеждает самый громкий сигнал, однако **все** флаги остаются в строке — второй
признак от врача не прячется. Связь без подозрений тоже попадает в очередь:
отсутствие структурного сигнала не доказывает корректность.

Первая пятёрка (`HIGH`):

| Нозология | КР | Почему подозрительно |
|---|---|---|
| `postop_prophylaxis` | 1702 «Воспалительные поражения позвоночника» | совпадение только по `Y83` — код обстоятельств операции |
| `pid` | 1556 «Туберкулез у детей» | КР детская, нозология `["adult"]` |
| `cdi` | 804 «Кампилобактериоз у детей» | КР детская, нозология `["adult"]` |
| `intraabdominal_infection` | 2042 «Острый аппендицит и перитонит у детей» | КР детская, нозология `["adult"]` |
| `sbp` | 2042 «Острый аппендицит и перитонит у детей» | КР детская, нозология `["adult"]` |

```bash
python -m clinical_engine.crosswalk.review_queue            # только отчёт
python -m clinical_engine.crosswalk.review_queue --write    # записать артефакт
```

Артефакт: `clinical_engine/resources/calculator_crosswalk_review_queue.json`
(детерминирован, ссылается на `content_sha256` кроссволка, поэтому рассинхрон
виден). Записи совместимы с `ReviewStore.import_issue` через `to_issue_records()`
и идемпотентны по `issue_id = xwblock_{disease_id}_{guideline_id}`.
